# Provisional exchange pairing

`pair-exchanges <dir> <capture-id> [max-lag-ms] [offset] [limit<=100]` proposes earlier/later message pairs inside one capture. The default maximum lag is 1000 ms. It uses timestamps and reciprocal direction strings; when ports are present, they must also be reciprocal. It pairs a later observation only when exactly one unused predecessor in the reverse flow lies inside the time window. Two possible predecessors, identical timestamps, missing timestamps, missing direction, or a flow whose endpoints reverse to themselves do not create a pair. Ambiguous and unpaired observations remain visible in the counts and bounded previews.

This is a **candidate exchange**, not a causal request/response claim. Retransmissions, multiplexing, unsolicited messages, clock error, and unrelated traffic can invalidate a pair. The algorithm does not inspect bytes to choose a predecessor, so a shared field cannot silently force a pairing. Use a shorter capture or an intervention when ambiguous predecessors remain.

The response pages pairs by later packet time and reports the full pair, ambiguity, and unpaired counts for up to 10,000 observations per capture. Each pair includes IDs, ports, exact nanosecond lag as a decimal string, and equal byte ranges in the first 64 message bytes. For each earlier direction, `varying_equal_ranges` names positions that are equal within every pair in that group and vary across at least three pairs. These positions are **measurements**, not confirmed echoed fields: a dependent checksum byte can satisfy the same rule. Compare an independent capture with changed payloads, run `infer-checksum` where applicable, and inspect the source byte spans before assigning semantics.

The deterministic ICMP sweep yields 512 unambiguous pairs and varying equal ranges at `[6, 8)` for the sequence, plus `[3, 4)` for a checksum byte. The DNS UDP fixture yields six pairs after reciprocal port matching and a varying equal range at `[0, 2)` for its transaction ID. The report shows candidate exchanges and opens a selected pair in the byte comparison view.
