# Typed length-value evidence

`probe-tlv` tests a repeated record layout containing a fixed-width type field followed immediately by a fixed-width length field and a value. It uses the same bounded parser and source provenance as `probe-framing`; all spans are half-open offsets in the parent observation. The type remains raw hex bytes, so a code like `a1` is not assigned a name or meaning.

The model allows a preamble before the first element, a one- or two-byte type, a one-, two-, or four-byte length, big or little endian for multibyte lengths, and alignment of 1, 2, 4, or 8 bytes. `payload` lengths count only bytes after the length field. `total` lengths count the whole logical element. The response separates `logical_end` from aligned `end`; value bytes are `[value_start, value_end)`. A `complete` status means the model exactly consumes the observation. The same 256-element and 16-source-span-per-element response bounds apply. Use `span` for more bytes or provenance.

`infer-tlv` searches start offsets 0–8, type widths 1–2, length widths 1/2/4, and alignment 1/2/4. It requires two or more discovery observations in one trial, at least two complete elements per observation, and varying length values. It checks surviving layouts on observations in a distinct validation trial of the same experiment. Results include boundary failures, raw type profiles, how often each type occurs in distinct observations, and whether held-out elements reuse known type codes. A new held-out type is reported, not treated as a boundary failure. Up to 16 observations per trial and 64 KiB per observation are searched; at most 100 candidate layouts and 64 type profiles per candidate are returned. Truncation flags identify omitted profiles.

For a controlled test, vary value lengths across a length-field width boundary and vary record types independently. Place at least two elements in each file, and reserve whole files for validation. The deterministic `records_*.bin` fixture has a four-byte preamble, three type codes (`a0`, `a1`, `a2`), two-byte big-endian payload lengths, and two-byte alignment. The model predicts all boundaries in two discovery and two held-out files. The type codes recur across files while the values' lengths change.

To persist the derived record IDs, use `commit-framing` with the same start, type width as its `field-offset`, length width, byte order, length mode, and alignment. For example, a TLV probe with `4 1 2 big payload 2` maps to `commit-framing ... 4 1 2 big payload 2 <key>`. The committed run stores boundaries and source spans; the raw type can be read using `frame-span` at `[0, type_width)` or inferred from controlled annotations with `frame-value` and `infer-frame-value`.

The search establishes candidate structure, not semantic type meaning. It does not parse nested TLVs, varint lengths, type-dependent length encodings, indefinite lengths, or checksums. Those should be separate hypotheses tested against independent captures and counterexamples.
