# Unsigned LEB128 record-length evidence

`probe-varint` tests repeated records whose length is an unsigned LEB128 integer. Each candidate sets a first-record offset, the length field's offset within each record, whether the decoded value counts the whole logical record or only bytes following the variable-width length field, and record alignment. The parser accepts canonical one- through five-byte encodings of `u32`; truncated, overlong, and overflowing encodings stop with explicit statuses. It returns the same half-open record boundaries and source-file or packet spans as `probe-framing`. The logical end excludes alignment padding.

`infer-varint` searches first-record offsets 0–8, length-field offsets 0–2, total and payload lengths, and alignments 1/2/4. It requires at least two discovery observations with two or more complete records each, varying decoded lengths, and at least one multibyte prefix. A separate validation trial in the same experiment supplies held-out checks. Every discovery fit is retained up to 100 reported candidates; each carries its validation count and structural counterexamples. The search accepts at most 16 observations per trial and 64 KiB per observation. A candidate's exact fit establishes boundaries under one model, not the semantic purpose of the field.

The deterministic `varint_*.bin` fixture crosses the 127/128-byte encoding boundary. Its independent truth file records every prefix and byte span. Two discovery files admit two candidate starts; only the start at byte 4 fits both held-out files. Inspect the failed alternative before accepting the surviving candidate. Corrupting a validation prefix produces a named counterexample without changing the discovery fit.

This first varint model does not persist derived frame IDs. Keep the raw observations and inference JSON, and use `span` to inspect exact bytes. Durable variable-width frames, signed zigzag encodings, base-128 big-endian variants, and nested records remain separate work.
