# Held-out frame CRC32 evidence

`infer-frame-crc32 <dir> <discovery-run-keys-csv> <validation-run-keys-csv>` tests whether the last four **logical** bytes of committed fixed-width frames store a standard reflected IEEE CRC32. The model computes CRC32 over frame bytes `[coverage_start, logical_end - 4)`, with a searched `coverage_start` from 0 through 16 and either stored byte order. Alignment padding after `logical_end` is excluded. The result uses frame-relative coordinates and stable frame IDs for counterexamples.

Select one committed framing run per observation. All selected runs must have the same boundary rule, even if their `total` and `payload` descriptions differ algebraically. Each run-key set must belong to one trial, and the trials must differ while belonging to the same experiment. Discovery needs two independent captures; validation needs at least one. The tool reads every selected frame, with caps of 16 runs per set, 512 frames and 512 KiB of logical bytes per set. A discovery candidate must match every discovery frame and show at least two different CRC values. Validation matches and up to 20 counterexample frame IDs remain visible; a candidate can survive discovery and fail validation.

The PNG fixture's four-byte length is outside the CRC coverage. Its type and data begin at frame offset 4, and its big-endian CRC32 occupies the last four logical bytes. Committing the same adjusted chunk model on two discovery PNGs and one held-out PNG yields a `coverage_start: 4` candidate that matches all four held-out chunks. A validation copy with one flipped CRC byte returns the exact contradicting frame ID. Valid RIFF/WAV chunks yield no candidate under this model.

An exact fit supports this narrowly stated equation. It does not establish a field's semantic purpose or cover other CRC polynomials, initial values, xor values, reflected variants, non-suffix storage, or checksums over external bytes. If no candidate appears, inspect `frame-span` and test another coverage model. For the original ICMP whole-message 16-bit checksum, use the separate [checksum method](checksum-method.md).
